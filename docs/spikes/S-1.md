# Spike S-1 — Postgres append design

**Status:** DONE · **Date:** 2026-11-09 · **Time-box:** ≤ ½ day · **Precedes:** T-1.02, T-1.03
**Proof script:** `docs/spikes/S-1.sh` (throwaway — it writes no production code)

---

## 1. What was confirmed

The four claims the pack requires, each confirmed by running the claim, not by reading the docs.

| # | Claim | Result | Evidence |
|---|---|---|---|
| 1 | `seq` is **gapless under 50 concurrent writers** | ✅ **CONFIRMED** | 50 parallel sessions + 50 sequential appends → 101 events, 100 distinct `seq`, span 100, `gapless = true` |
| 2 | **Row triggers fire on partitions** | ✅ **CONFIRMED** | `AFTER INSERT` trigger on the partitioned parent fired; `trigger_log` had 1 row |
| 3 | The app role **truly cannot** UPDATE/DELETE/TRUNCATE | ✅ **CONFIRMED** | `SET ROLE factory_app` → all three statements raised `permission denied for table events` |
| 4 | The NOTIFY payload carries **only `seq`** | ✅ **CONFIRMED** | Listener received payload `"102"` while the event body was 5 000 bytes |

### 1.1 Gaplessness under concurrency

```
 total | distinct_seq | min_seq | max_seq | span | gapless
-------+--------------+---------+---------+------+---------
   101 |          100 |       1 |     100 |  100 | t
```

50 sequential appends, then 50 **concurrent** sessions each calling the append function.
The counter row is updated with `UPDATE … RETURNING value`, which takes a row lock; the
concurrent callers serialise on it. The resulting `seq` values are contiguous.

### 1.2 A rollback does not consume a `seq`

This is the property the whole design rests on, and it is *not* automatic — it is a
consequence of the counter increment being in the **same transaction** as the insert.

```
 counter_after_rollback : 101
 total_events            : 102
 distinct_seq            : 101
 span                    : 101     still_gapless: true
```

An append inside a subtransaction that is rolled back leaves the counter where it was and
leaves no gap. **Consequence for T-1.03: the counter update and the event insert must be in
one transaction.** Any design that increments the counter outside the transaction's commit
boundary breaks gaplessness.

### 1.3 The app role's write restrictions

```
--- as factory_app: UPDATE ---   ERROR:  permission denied for table events
--- as factory_app: DELETE ---   ERROR:  permission denied for table events
--- as factory_app: TRUNCATE --- ERROR:  permission denied for table events
```

Grants were `SELECT, INSERT` only. Note that `TRUNCATE` is denied by the same rule — it is
not a separate privilege, so a role that has never been granted `TRUNCATE` cannot use it.

### 1.4 The NOTIFY payload

```
Asynchronous notification "spike_s1_events" with payload "102" received from server
process with PID 1939.
```

The event body was 5 000 bytes; the notification carried 3 bytes. `pg_notify` payloads are
text and are limited to 8 000 bytes — carrying the event body would have been near the limit
and would have coupled the notification size to the event size. **Confirmed: the design of
notifying `seq` only is correct and safe.**

## 2. Findings that change the implementation

### 2.1 A partitioned table's PRIMARY KEY must include the partition key

**This was a real error in the first draft of the spike script**, and it is worth recording
because T-1.02 writes the DDL:

```
ERROR:  unique constraint on partitioned table must include all partitioning columns
DETAIL:  PRIMARY KEY constraint on table "events" lacks column "created_at" which is part of
         the partition key.
```

A `PRIMARY KEY (seq)` on a `PARTITION BY RANGE (created_at)` table is rejected outright.

**The pack's DDL already has this right.** Pack `03` §2:

```sql
PRIMARY KEY (seq, occurred_at)
) PARTITION BY RANGE (occurred_at);
```

The spike's first draft used `PRIMARY KEY (seq)` and was corrected to the pack's shape.
**No change to the pack is needed.** T-1.02 must copy the pack's DDL **verbatim**, and this
spike is the evidence that the pack's shape is the one Postgres accepts.

### 2.2 The default partition works

`CREATE TABLE events_default PARTITION OF events DEFAULT` was created and accepted. Pack `03`
§2 includes it, and the T-1.02 oracle requires that "default partition catches out-of-range
rows". The mechanism is confirmed; the oracle still has to verify the *catching*.

### 2.3 `max_connections = 100` in the dev cluster

The dev cluster is configured with `max_connections=100` (`docker-compose.dev.yml`). The
spike's 50 concurrent sessions fit comfortably. **This is a dev-only setting.** The
production host's `max_connections` is an operational decision for checklist 10 and is not
settled here.

## 3. Findings that need an owner decision

### 3.1 The MinIO image reference in `docker-compose.dev.yml` is dead

**Finding.** The image `minio/minio:RELEASE.2024-10-13T13-34-11Z` in
`docker-compose.dev.yml` **cannot be pulled**:

```
Error response from daemon: pull access denied for minio/minio, repository does not exist or
require 'docker login'
```

The repository `minio/minio` on Docker Hub **no longer exists**. MinIO's community/open-source
edition was archived (the upstream repository was archived on 2026-02-13) and its images were
removed from Docker Hub.

**This is a defect in the compose file, not a network problem** — a 404 from the registry is
different from a timeout, and Postgres 16-alpine pulled successfully from the same daemon in
the same session.

**The successor image could not be determined from this environment.** Docker Hub's API and
`quay.io/minio/minio` were both unreachable or unauthenticated from here, and the pack's
HR-11 forbids coding against a remembered reference:

- `quay.io/minio/minio:latest` → `401 UNAUTHORIZED`
- `hub.docker.io/v2/namespaces/minio/repositories/minio` → unreachable
- `github.com/minio/minio/releases/latest` → unreachable

**Owner action required.** The `minio` service in `docker-compose.dev.yml` needs a current
image reference, verified against the official MinIO distribution channel and recorded here
with its source and date. **Do not** substitute a guessed tag.

**What this blocks.** The bucket is not needed for S-1, and nothing in W0 depends on it
beyond T-0.01's "Postgres + bucket" step. It **does** block checklist 02's database work if
run artefact storage (T-1.11) needs the bucket early.

**Interim state.** The `minio` service is left in the compose file with a note; the dev
cluster runs Postgres only. The Postgres service was verified healthy and is what S-1 ran
against.

## 5. What this changes for the pack

**Nothing in the pack needs to change.** The pack's DDL already uses the PK shape Postgres
requires, and the pack's `NOTIFY`-with-`seq` design is confirmed safe.

Two things follow for **T-1.02**:

1. The DDL is copied **verbatim** from pack `03` §2 — including `PRIMARY KEY (seq,
   occurred_at)`. This spike is the evidence for why that clause is not optional.
2. The oracle's "default partition catches out-of-range rows" check has a confirmed
   mechanism behind it.

And one thing follows for **T-1.03**:

3. The counter increment and the event insert are in **one transaction**. Gaplessness under
   rollback is a property of that transaction boundary, not of the counter table.

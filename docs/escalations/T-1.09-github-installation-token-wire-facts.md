# ESCALATION · T-1.09 · the GitHub installation-token wire facts are unconfirmed (S-2)

- **Ticket:** T-1.09 — Credential broker and secret store (checklist 03, R4)
- **Trigger:** AGENTS.md §6 — *"an external fact differs from the ticket/spike"*;
  HR-11 — a `[VERIFY]` fact must be confirmed from official documentation or
  a spike note before it is relied upon
- **Status:** the credential machinery is complete and green; **the real
  GitHub adapter does not exist**, because the two wire facts it would need
  are unconfirmed.

---

## What I was doing

Building `packages/credentials` — the secret store, the scope computation, the
credential broker, the lease store, the redaction registry, the orphan reaper
and the fake provider.

The ticket's last clause is: *"GitHub-installation-token minting (narrowed)"*.
That minting is a **wire** operation against GitHub's API: sign a JWT with the
App's private key, `POST` it to the installation's token endpoint, receive an
installation token, and later `DELETE` it to revoke.

## Evidence

| Fact | Source |
|---|---|
| The checklist names **S-2 done** as a **prerequisite** for T-1.09 | `checklists/03-*.md:19` — "S-2 done (GitHub App mechanics) — blocks T-1.09" |
| **S-2 does not exist** | `docs/spikes/` contains **S-1** only; there is no S-2 note |
| S-2 needs a **real GitHub App**, which is an owner action | creating an App, installing it, and keeping its private key is not a code change |
| The two wire facts are tagged `[VERIFY]` in the pack | pack 04 §2.2 — the mint request body's narrowing semantics and the revoke call's shape |
| ADR-0018 requires a **per-task installation token**, narrowed to one repo and minimum permissions, TTL ≤ 1 h | blueprint ADR-0018 |

So: the *facts* the minting depends on are precisely the facts that have not
been confirmed, and the mechanism for confirming them needs an owner action
that has not happened.

## Why I did not just write the adapter

- **HR-11:** a `[VERIFY]` fact must be confirmed from official documentation
  or a spike note. Writing the adapter against an *unconfirmed* request body
  would put the factory's guess about GitHub's API into the code that mints
  the factory's credentials — and a wrong guess there fails in the most
  expensive way possible: a credential that is scoped wrongly, or a mint that
  silently grants more than intended.
- **AGENTS.md §6:** "an external fact differs from the ticket/spike" is a
  stop-and-escalate trigger. The ticket's prerequisite is unmet.
- **The instruction to be careful with secrets.** Writing a real adapter
  means handling `GITHUB_APP_PRIVATE_KEY`. HR-9 forbids real secrets in
  tests and fixtures, and AGENTS.md §6's trigger list includes *"you would
  need a secret"*.

## What I did instead

The minting sits behind a **port** — `CredentialMintProvider`
(`packages/credentials/src/broker.ts:167`) — and everything that is *the
factory's own logic* is built and proved **now**, against the fake:

| The factory's logic | Where it lives | How it is proved |
|---|---|---|
| the scope computation (the **intersection**) | `packages/credentials/src/scope.ts` | `tests/unit/credentials-scope.test.ts` (16 tests) |
| the lease — reference, never material | `packages/credentials/src/broker.ts`, `packages/credentials/src/postgres/lease-store.ts` | `tests/unit/credentials-broker.test.ts`, `tests/acceptance/credentials/T1_09_credentials.test.ts` |
| the TTL ceiling (≤ 1 h) and the provider-expiry bound | `packages/credentials/src/scope.ts`, `packages/credentials/src/broker.ts` | `tests/unit/credentials-scope.test.ts`, `tests/unit/credentials-broker.test.ts` |
| the revocation at every terminal state | `packages/credentials/src/broker.ts` (`revokeAll`) | `tests/unit/credentials-broker.test.ts` |
| the orphan reaper | `packages/credentials/src/broker.ts` (`reapExpired`) | `tests/unit/credentials-broker.test.ts` |
| the redaction set | `packages/credentials/src/redaction.ts` | `tests/unit/credentials-redaction.test.ts` (22 tests) |
| the secret store | `packages/credentials/src/secret-store.ts` | `tests/unit/credentials-secret-store.test.ts` (20 tests) |
| the credential’s **use-after-revoke** failure (A3.4) | `packages/credentials/src/fakes/fake-credential-provider.ts` (`use`) | `tests/unit/credentials-broker.test.ts` |
| the **secret scan** — no token in any event, log, artefact or prompt | the broker’s own behaviour | `tests/unit/credentials-broker.test.ts` |
| the wiring into the tool broker’s step 7 | `packages/credentials/src/broker-provider.ts` | `tests/unit/credentials-broker-integration.test.ts` |

The **fake provider enforces the revocation** — `use(credId)` throws for a
revoked credential — so A3.4 is a **real** failure rather than a simulated
one. That is why the fake, not the real adapter, is where the acceptance
criterion is proved.

What is missing is only the **adapter**: the thin shim that turns a
`MintRequest` into GitHub's two wire calls and back.

## The gap this leaves, stated plainly

The factory can mint a credential **against the fake**, and it can hold,
scope, lease, redact and revoke that credential against a **real database**.
What it cannot yet do is mint a credential against **GitHub**.

That is a genuine gap and it is not hidden:

- `CredentialMintProvider` has exactly **one** implementation in the tree —
  the fake. There is no half-built real adapter left in place.
- The `SECRET_INVENTORY` names `GITHUB_APP_PRIVATE_KEY` as **worker-only**
  secret material, so the worker process is the one that would hold the
  key — and the worker is T-1.13's work.

## Options, with consequences

**A — Run S-2 and add the adapter (recommended).**

The owner creates a GitHub App, installs it on a throwaway repository, and
records in `docs/spikes/S-2-github-installation-token.md`:

- the exact mint request body and its response shape;
- the exact revoke call and its response;
- the real token lifetime observed (ADR-0018 assumes ≈ 1 h);
- whether the App's installation can be narrowed per repository per task, or
  whether narrowing happens only in the token's permissions.

The adapter is then a small file: it signs the JWT, makes the two calls, and
maps the responses onto `MintResult` and the `revoke` port. Every rule the
adapter *depends on* is already proved.

Blast radius: the adapter touches the worker's secret material, so it needs
the `[VERIFY]` facts to be right and a **real-token smoke test** — which is
precisely the checklist's own last clause for this ticket (*"a real-token
smoke recorded in S-2"*).

**B — Write the adapter now against the published GitHub documentation,
without a spike.**

Rejected. The documentation is authoritative for the *shape* of the calls, but
ADR-0018's narrowing semantics — specifically whether the token's repository
list can be narrowed per task, or only its permissions — is the question the
spike exists to answer, and getting it wrong produces a credential that is
**broader** than the factory believes. That is the failure mode the whole
ticket exists to prevent.

**C — Ship the port and the fake, and leave the adapter for T-1.13.**

Acceptable as the immediate state; it is what this ticket ships. The cost is
that the factory's credential path is **unexercised against GitHub** until
the worker exists, so the first real mint is also the first real test.

## Recommendation

**Option A**, before T-1.13 (the orchestrator/worker) is started. The worker
is the component that would hold `GITHUB_APP_PRIVATE_KEY` and make the first
real mint; arriving at that point without S-2 would mean discovering the wire
shape in the middle of the worker build, which is the worst time for it.

If the owner prefers, **Option C** for now is defensible — nothing is blocked
*by* the gap, because the worker's credential path is T-1.13's work anyway.
But S-2 should be scheduled, because T-1.13 depends on it.

## What I have NOT changed

- `packages/contracts/**` — untouched.
- `docs/spikes/**` — untouched; **S-2 has not been written**, because writing
  it would require the real App and the real token smoke, which is the
  owner's action.
- No `[VERIFY]` fact has been guessed into the code. The port's doc comment
  names the two unconfirmed facts and says that S-2 has not run.
- The real GitHub adapter has **not** been sketched, even in a disabled
  branch — a half-written adapter against unconfirmed facts is exactly the
  thing that gets "finished" later by someone who does not know it is a
  guess.

# ESCALATION · T-1.12 · the T1 isolation tier needs two R4 changes the ticket does not name

- **Ticket:** T-1.12 — T1 isolation (snapshot / clean worktree) (checklist 03, R3/S)
- **Trigger:** AGENTS.md §6 — *"an external fact differs from the ticket/spike"*;
  the ticket asks for *"reclamation + a leak detector"*, and both of those
  need a **durable record** and an **event**, which live in R4 paths the
  ticket does not name
- **Status:** the `packages/isolation` package is complete and green. All
  three proofs pass, 25 named mutations are caught, and the two R4 changes
  are **not** made — they are shipped as ports with in-memory doubles.

## The two boundaries

### 1. The snapshot registry needs a table — `migrations/**` is R4

A **leak detector** needs to know what *should* exist, so it can report
what does. A **reclaimer** that works after a crash needs the same thing,
because a crashed task cannot be asked what it owned.

So there must be a **durable record of the workspaces that exist**. In
Postgres that is a table, and `migrations/**` is **R4** — a path the ticket
does not name.

T-1.12 therefore ships the registry as a **port** (`SnapshotRegistry`) with
an in-memory double, and the Postgres implementation is left to T-1.13 or
T-1.15.

This is **not** a design dodge. The reclaimer's logic does not depend on
the store: it walks the registry, checks each workspace's task state, and
removes the ones whose task is terminal. The store is a detail behind a
port, and the port's contract is one page long.

### 2. There is no event type for a T1 snapshot — `packages/contracts/**` is R4

The isolation package **emits no events**. The two candidates that already
exist are both wrong for T1:

| Event | Why it does not fit |
|---|---|
| `environment.provisioned` | Its payload is `['envId','tier','imageDigest','limits']` — `imageDigest` is a **T2** concept. A T1 snapshot has no image. |
| `environment.cleaned` | Its payload is `['envId','reason']` — it names an `envId`, not a workspace root. |

And a **new** event type cannot be added here: `packages/contracts/**` is
R4, and a new type needs an entry in `packages/contracts/events.md` or
contract test A1.19 fails CI.

So the snapshot's lifecycle is currently **invisible to the event log**.
A run that took a snapshot leaves no trace there.

## Why this is an escalation and not a ticket-blocking gap

Nothing in the ticket's proof is blocked:

| The rule | Where it lives | How it is proved |
|---|---|---|
| reclaimed at every terminal state **including failure** | `packages/isolation/src/t1/reclaim.ts` | `tests/unit/isolation-a0-9.test.ts` |
| `ESCALATED` does **not** reclaim (it is resumable) | `packages/isolation/src/t1/reclaim.ts` | `tests/unit/isolation-a0-9.test.ts` |
| git is invoked with hooks disabled (spy assertion) | `packages/isolation/src/t1/snapshot.ts`, `worktree.ts` | `tests/unit/isolation-a0-9.test.ts`, `tests/unit/isolation-worktree.test.ts` |
| traversal in a snapshot request is rejected | `packages/isolation/src/t1/paths.ts`, `snapshot.ts` | `tests/unit/isolation-paths.test.ts`, `tests/unit/isolation-snapshot.test.ts` |
| the leak detector reports what is left behind | `packages/isolation/src/t1/reclaim.ts` | `tests/unit/isolation-a0-9.test.ts` |

What is blocked is **durability**: the registry is in memory, so a process
restart loses the record of what exists, and the leak detector cannot see
a snapshot that was created before the restart.

## Options, with consequences

**A — Add the table and the events in a contracts/migration ticket
(recommended).**

The owner opens a ticket that touches `migrations/**` and
`packages/contracts/**` together, adds a `workspaces` table and a
`snapshot.taken` / `snapshot.reclaimed` event pair, and T-1.13 (or T-1.15)
wires them in.

Blast radius: one migration, two event types, two `events.md` rows, and
the Postgres implementations of the two ports. The isolation package's
logic does not change — only the two adapters behind the ports.

**B — Keep the in-memory registry and have the orchestrator own the
durability.**

T-1.13's orchestrator already has a task table and an event log. It could
record the workspace's existence as an **event** and reconstruct the
registry from the log on startup — which is, in effect, the event-sourced
version of option A, using the existing `events` table and no new
migration.

Blast radius: no new migration, but a **projection** over the event log —
which is exactly what T-1.15 ("Projections and rebuild") is for. So option
B is really "defer the table to T-1.15".

**C — Ship as-is and let the reconciler discover the workspaces by
scanning the filesystem.**

The leak detector already walks the workspace root. If the *registry* were
derived from the filesystem rather than a table, there would be no durable
record to maintain, and no migration.

Blast radius: small — but it changes what the registry **is**. The
registry's job is to be the durable record of what the factory *claims*
to own; a filesystem scan cannot distinguish a factory workspace from
anything else in the directory. It also loses the task↔workspace
mapping, which the reclaimer needs.

## Recommendation

**Option A**, because the durability is the point of the rule.

ADR-0006 §4 is explicit: *"Cleanup is a reconciler responsibility
(ADR-0001), so a crashed task's resources are reclaimed rather than
leaked."* A reconciler can only reclaim what it knows about, and a
registry that dies with the process is not a reconciler's record — it is
the process's memory.

Option B is the honest fallback and it is **not blocked**: T-1.15's
projections exist precisely to rebuild state from the event log. If the
owner's preference is to avoid a new table, the events alone would carry
the workspace's lifecycle, and the projection would rebuild the registry.

Option C is not recommended. It trades a durable record for a filesystem
scan, and the scan cannot answer the question the reclaimer asks.

## What I have NOT changed

- `migrations/**` — untouched. No table was added.
- `packages/contracts/**` — untouched. No event type was added, and
  `packages/contracts/events.md` was not edited.
- **The T2 tier** — untouched. ADR-0020's T2 (rootless Docker) is a
  different tier and a later ticket; this ticket is T1 only.
- **The S3-shaped wire facts** — none. This ticket runs `git`, and the
  spawn is injected, so no test reaches a real `git` binary's side effects
  beyond a temp directory (`tests/unit/isolation-tar-real.test.ts` runs a
  real `git archive` in a temp repository, and nothing else).
